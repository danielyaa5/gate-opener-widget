# Regenerate screenshots and the demo video

Run this on a development Mac with Xcode command-line tools, FFmpeg and the
project's camera dependencies installed:

```sh
.venv/bin/python -m pip install -r requirements-camera.txt
brew install ffmpeg
.venv/bin/python scripts/generate_demo_media.py
```

The command replaces these files under `docs/images/`:

- `mac-app.png`: app screenshot with camera status, latest picture and Ring link.
- `mac-widget.png`: desktop widget screenshot.
- `demo.gif`: looping README preview.
- `demo.mp4`: H.264 video showing Closed, a sent command, possible movement, Open, and Closed again.
- `demo-media.json`: source and output hashes, dimensions, duration and provenance.

Use `--output /path/to/review` to review new assets before replacing the committed
ones. Open the PNGs and watch the MP4 before committing. The source hashes in the
manifest identify exactly which presentation code was used.

The script compiles the app's real `GateDashboardView` and `GateWidgetView`, renders
them offscreen with SwiftUI `ImageRenderer`, and encodes the resulting frames.
The small title bar and simulated-demo caption are a recording wrapper. The
camera view is an illustration generated by `scripts/demo_camera.py`; it is
explicitly marked simulated. The sequence demonstrates UI states, rather than
recording mouse input or exercising the app's system confirmation dialog.

No screen recording permission, browser, running bridge, login, signing certificate
or real camera is required. It does not load `.env`, saved connection settings,
Keychain entries or camera files, and never sends a gate command or makes network
requests. It opens no windows and removes its temporary compiler/encoding files
when finished. There is no native app to install or register in Spotlight.

For an interactive app check, `scripts/demo_bridge.py` also provides a loopback-only
simulated bridge, camera pictures and Open/Closed observations. Use a separate demo
app identity for that check; do not replace the connection in an installed real app.

## Hardware photographs

`elite-operator.jpg` and `elite-control-board.jpg` are original archival photos
supplied for the project story, separate from the simulated app media. They show
the existing Elite operator and control board; the Aubric add-on is not shown.
They are not a wiring-terminal diagram for the Aubric connection.

The published copies preserve the original image pixels and color profile, with
EXIF, IPTC and XMP metadata removed. Keep these photographs separate from camera
calibration images and do not replace them when regenerating the demo. The media
script does not create or modify them.
